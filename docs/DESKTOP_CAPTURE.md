# 桌面与多平台采集 · 0.5.0 Beta

## 接入方式

| 方式 | 平台 | 当前能力与验证状态 |
| --- | --- | --- |
| 本地文件监听 | Codex、Claude Code | 持续同步，已有解析、去重与 Electron 冒烟验证 |
| Mac 窗口采集 | 豆包、ChatGPT、Claude、Cursor、Windsurf、Trae、其他自定义应用 | 通用辅助功能接入：读取一个窗口、人工勾选用户提问、入库；各客户端真实登录态尚未验收，不代表全量自动兼容 |
| 浏览器扩展 | 豆包、DeepSeek、Kimi、通义/Qwen、腾讯元宝、ChatGPT、Claude、Grok、Manus、Genspark | 内置待验证模板；必须先预览并逐站授权，开启后持续同步当前已加载用户消息 |
| 文件导入 | ChatGPT/Claude/Grok 原生格式，以及任何平台的通用 JSON | 通用格式显式声明来源与角色，不以模型名称猜测来源 |

## Mac 窗口采集

1. 在目标应用打开一段对话。进入 Personal Memory 的「采集来源」。
2. 点击「授权辅助功能」，在 macOS 系统设置中允许 Personal Memory。授权由操作系统控制，应用不能绕过；拒绝授权仍可使用文件导入或网页扩展。
3. 「刷新应用列表」，选择运行中的应用及对应来源平台。自定义来源填写独立平台标识（字母、数字、点、横线、下划线）。
4. 为这段对话填写唯一标识；重复采集同一段对话复用它，新对话务必换一个。窗口标题不被当作可靠的会话 ID。
5. 「读取窗口预览」后，只勾选已发送的用户提问。可访问文本包括助手回答、标题和界面文字，**程序不会自动判定其角色**。如一条提问被拆成多段，勾选的每段会作为独立记录。
6. 确认入库，在「记忆工作台」按平台查看。分析仍需另行预览、确认，不会自动调用 AI。

仅执行一次所选应用的窗口读取，不监听键盘、不截图、不常驻扫描。读取静态可访问文本，跳过文本编辑器、密码框、可编辑子树，不采集未发送草稿。预览只在内存中保留，不写日志或数据库；10 分钟后不能确认，下一次预览覆盖前一次。关闭应用清除；关闭页面只是隐藏预览，内存最多保留到下一次读取/暂停/清空/退出。确认仅接受原始预览中的节点 ID，界面不能注入未预览文本。暂停后无法读取或入库。

原生 helper 使用 AppKit / ApplicationServices 编译，随 Mac 安装包提供；不依赖用户安装 Swift。开发 Mac 需 Xcode Command Line Tools，运行 `npm run build:native`。Linux 不能读取 Mac 窗口，也不能验证真实客户端兼容性。GitHub Mac 构建会编译并启动 helper 的应用枚举模式；这不是各客户端实测。

## 范围与去重

- 只读取目标应用的一个当前窗口中通过辅助功能开放的文本。客户端不开放该树、只绘制画布、权限受限或窗口不存在时无法读取；可能没有数据。不会绕过客户端加密或读取 Cookie、登录凭据。
- 对话按「平台 + 应用 bundle ID + 用户填写的对话标识」隔离；网页和文件导入使用独立会话命名空间，不跨渠道合并。
- 窗口缺少可靠消息 ID：按文本及本次所选同文出现序号去重。编辑视为新消息，部分历史加载、重复文本重排、误用对话标识可能造成合并或重复；不会承诺精确还原完整历史。
- 通常无法获取原始发言时间，明确显示采集时间，不用于推断历史事件的发生时间。
- 无自动滚动、无后台持续采集、无自动区分助手/用户。需要无人值守采集时，优先使用已验证的本地文件或网站规则。

## 通用导入格式

见 [示例](../examples/conversations.json)。这是 Personal Memory 的接入协议，**不是声称豆包或其他厂商原生导出就是这种格式**。平台原生导出不同需转换或单独适配。

```json
{
  "format": "personal-memory.conversations.v1",
  "provider": "doubao",
  "conversations": [{
    "id": "my-conversation-001",
    "title": "产品需求",
    "messages": [
      {"id": "user-1", "role": "user", "text": "请使用白色背景。", "timestamp": "2026-10-22T08:00:00Z"},
      {"id": "assistant-1", "role": "assistant", "text": "好的。"}
    ]
  }]
}
```

`provider` 可用 `codex / claude / chatgpt / grok / manus / genspark / doubao / deepseek / kimi / qwen / yuanbao / cursor / windsurf / trae` 或 `custom:my-agent`。只有 user 角色入库；同平台、同会话和消息 ID 重导入更新，消息 ID 必须稳定且在会话内唯一。缺少时间时使用采集时间并明确标注。导入文件与数据库未单独加密。

旧的 `messages` / `role` / `content` 格式不再默认归为 Grok：必须在顶层或每段对话显式填写 `provider`，防止豆包等同形数据被误标。已有数据库记录不变；ChatGPT mapping 和 Claude chat_messages 仍按各自结构识别。
