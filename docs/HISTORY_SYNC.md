# 历史对话同步

v0.6.0 的空白工作台、「采集来源」和设置页提供历史同步入口。默认不开启后台采集；同步历史不需要 OpenRouter Key，也不会自动分析或上传。

## Codex

1. 点击「同步 Codex 历史」。扫描 Codex 数据目录里的 `sessions` 和 `archived_sessions`，递归读取全部 `.jsonl`。
2. 查看扫描文件数、新增提问数、跳过文件及错误。可停止后再次扫描；重复数据不会再新增。
3. 如果没有找到会话，点击「选择目录」。默认目录为 `CODEX_HOME` 或 `~/.codex`；从 Finder 打开的应用通常没有终端的环境变量，建议直接选择实际目录。目录选择器显示隐藏文件，也接受选中 `sessions` / `archived_sessions` 后自动使用其父目录。
4. 勾选「持续同步 Codex 新提问」接收后续变化；它也扫描既有文件和归档。暂停采集会停止历史扫描；恢复后可再次同步。

范围是**本机已保存的 JSONL**。未落盘的云端对话、其他电脑的日志、已经被平台删除的文件不在范围内。没有找到 archived_sessions 本身不是故障，可能从未归档。

解析只保留用户消息，排除助手、工具结果和已识别的启动上下文。兼容 event_msg 与 response_item；混合格式保留旧消息，并合并相邻、正文相同且时间接近的双重表示。保存表示身份以便升级、修改和再次同步时保留已有提问 ID。无原生消息 ID 时仍依赖顺序，平台重写/重排日志可能需要进一步适配。

单文件上限 100 MB。一个坏文件不会阻塞其他文件；错误在页面展示。最后一行尚未写完的 JSON 被暂时忽略，下次扫描补入。文件或目录读权限错误会显示，不会自动修改源目录权限。

## 豆包

当前**没有自动拉取豆包整个账号历史**的能力，也没有经过真实客户端验证的豆包本地数据库/网络接口适配。Mac 窗口预览和浏览器扩展只读取已加载内容，不能据此宣称完整历史已同步。

点击「导入豆包历史文件」可一次选多个 JSON。支持 Personal Memory 通用格式，以及以下 messages 结构：

```json
{
  "provider": "doubao",
  "id": "stable-conversation-id",
  "title": "对话标题",
  "messages": [
    {
      "id": "stable-message-id",
      "role": "user",
      "content": "用户发送的提问",
      "timestamp": "2026-01-01T00:00:00Z"
    }
  ]
}
```

这是一种**支持的导入结构示例**，不代表豆包原生导出就是此结构。原生文件需要先确认结构并适配。为保证更新和去重，应提供稳定会话和消息 ID；缺少时采用内容/顺序推导，重排可能产生新记录。只有 user/human 消息入库，助手内容不采集；通过豆包入口导入且未声明 provider 的 messages 文件会标为豆包，已明确声明其他平台的文件拒绝导入，不强行改来源。单个失败文件不阻塞剩余文件。

## 验证边界

自动测试覆盖历史扫描、归档、混合格式、旧数据库身份迁移、重复导入、重启持久化、取消、坏文件继续处理和页面交互。Electron 测试使用临时目录中预先生成的历史样本，不接触个人数据。真实 Mac 上是否已入库，以应用显示的目录、错误和记录数为准。
