# 浏览器采集 · 0.3.3 Beta

支持 Chrome / Edge 扩展。不是浏览器插件商店发行版；目前以已解压扩展加载。Safari 暂未支持。

## 安装

1. 安装并打开 Mac 版 Tracelet。在「连接与设置 → 浏览器扩展」打开扩展文件夹；或从同一 GitHub Release 下载 `Tracelet-browser-extension.zip` 并解压。
2. 在 `chrome://extensions` 或 `edge://extensions` 开启开发者模式，加载已解压扩展。复制其 32 位 ID。
3. 在 Tracelet 中选择浏览器并输入 ID，点击配对。应用会为当前 macOS 用户写入该浏览器的 Native Messaging Host 清单，仅允许此 ID。
4. 打开一段有独立网址的 AI 对话，点击扩展的「预览用户消息」。逐条核对结果，确认均为已提交的用户提问后「授权并开启本站」。规则默认关闭；授权仅限该 HTTPS 来源。
5. 新增/变化的消息进入扩展本地队列，经原生消息管道交给本机桌面端。桌面未启动也可先入待导入目录，下次启动入库。断线每分钟重试，亦可手动同步。应用的来源列表会出现对应平台。
6. 选择对话 → 预览发送内容 → 确认 AI 分析 → 审核候选记忆。浏览器采集本身不调用 AI。

移动解压目录、换浏览器配置文件或重装可能改变扩展 ID，需重新配对。升级 Mac 应用后请在扩展管理页重新加载扩展以载入新脚本。无需向扩展提供 OpenRouter Key。

## 网站规则

Claude、Grok、Manus、Genspark、ChatGPT 内置**待验证选择器模板**，不代表已在登录态真实网站通过验收。模板可能匹配零条或错误内容，必须预览；网站改版需要调整。自定义站点在扩展「规则与数据」填写 HTTPS 来源与 CSS 选择器，按完整域名独立分类，不猜测使用的模型。

| 配置 | 用途 |
| --- | --- |
| 用户消息容器选择器 | 必填，只匹配单条已提交用户消息的节点 |
| 正文选择器 | 可选，在每个消息容器内提取正文，排除操作按钮等 |
| 稳定消息 ID 属性 | 可选，平台的 `id` / `data-*` 属性；同 ID 的编辑按采集版本时间更新同一条记录 |
| 会话 ID 查询参数 | 可选，使用 `?conversation_id=...` 等网址的网站必填；默认按来源与路径区分会话 |

不允许整页、通配符和输入框规则；还会排除可编辑区域、已识别的助手容器及嵌套重复。选择器无法证明消息已被服务器接收，只表示页面将其呈现在用户消息区域。预览不正确时不要启用。

## 去重与范围

- 会话 ID 为规范化网址与选定会话参数的 SHA-256；URL 查询和片段不落盘，但会话参数参与哈希。来源平台由桌面端验证过的域名决定，Claude Code 与 Claude 网页会话有不同标识。
- 消息有稳定 ID 时，重复同步幂等，原地编辑更新文本并重新进入待分析集合。已确认记忆的原文快照仍保留。离线入站文件按消息采集版本比较，较早的数据包不会覆盖后来的编辑；该时间来自本机时钟，系统时钟回拨可能影响比较。
- 无 ID 时以文本哈希及同文出现次数去重。编辑视为新消息；虚拟列表、历史重排、删除后的重复文本无法保证准确关联。
- 只采集当前页面已经加载的纯文本，不自动翻历史，不保证附件、图片、语音、iframe 或 Shadow DOM 支持。以哈希路由区分会话的网站目前不支持；用同一路径区分多会话的网站需提供稳定查询参数，否则不要启用。
- 通常取不到原始发言时间，界面明确标注「采集于」，分析输入附 `timeSource=captured`，不可据此推断历史事件日期或先后关系。
- 本地 Codex 与网页 Codex、从不同渠道导入同一对话，目前不跨渠道合并，以免误删独立来源。

## 数据流与暂停

`已授权站点 DOM → 扩展 storage.local 副本 + 待同步队列 → Native Messaging → 本机 browser-inbox → SQLite trace → 人工选择/预览 → OpenRouter → 待确认记忆`

没有 localhost HTTP 监听端口。Host 校验 HTTPS 来源、消息角色、大小和结构，使用 4 字节小端帧，单帧不超过 1 MiB；先以 0600 权限原子写盘才确认接收。桌面数据库完成持久化后删除入站文件。扩展约 4 MiB 达上限时显示错误并停止写入，不静默丢弃历史，可导出后清理。

应用暂停桌面同步或关闭接收时，扩展继续在本站采集并保留本地队列。停止采集请在扩展中暂停本站或撤回站点权限。扩展副本明文保存在浏览器用户配置目录；应用中清空数据库不会清空扩展副本。彻底清理需先暂停扩展，再清空两端，另行删除导出文件和备份。重新启用可能再次导入页面历史。

## 已验证与未验证

自动检查覆盖：DOM 合成页面中的用户/助手/草稿分离、嵌套重复、相同文本的独立消息、编辑、SPA 会话切换、自定义查询参数、帧大小；扩展后台的授权与队列重试；Native Host 真实子进程帧通信、持久化、暂停；SQLite 迁移与幂等；真实 Electron 主进程的 Host→inbox→数据库链路。

尚未验证：真实 Chrome/Edge 配对后的端到端浏览器权限流程，以及各网站登录态 DOM。发布前/站点改版后，应在本人授权的测试会话中核对「用户消息条数、原文、会话隔离、刷新去重、编辑、暂停、断网恢复」，通过后再启用该站点。没有实测模型准确率，现有 Agent 测试以合成样本与结构约束为主。
